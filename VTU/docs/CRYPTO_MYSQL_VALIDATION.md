# Disposable MySQL integration validation

`tests/crypto_mysql_integration.php` exercises the actual production schema, prepared-query helpers, governance and reservation functions against MySQL 8, separately for each edition. It does not load application configuration, call providers, or use an existing application database.

## Safety boundary

Use a dedicated disposable MySQL server, **never production or shared staging**. The explicit `BC_CRYPTO_TEST_MYSQL=DISPOSABLE_ONLY` acknowledgement is mandatory. The test credentials need CREATE/DROP DATABASE, trigger privileges and read access to `performance_schema.data_lock_waits` and `performance_schema.threads`. Those are test-runner privileges, **not recommended application grants**.

The runner creates a cryptographically random `crypto_ci_<24 hex characters>` database, selects it, and installs seven additive tables plus a minimal synthetic `sas_users` fixture. It drops only that generated database in `finally`. A killed process or server outage can leave an orphan; clean it up only on the isolated test server after verifying no test is active. No existing database name is accepted as a runner input. Worker database arguments are validated and generated by the parent runner.

Synthetic balances and reconciled flags are test fixtures only. They do not implement or authorize production opening entries, custody attribution or provider reconciliation.

## Running

Requires PHP CLI with mysqli/mysqlnd and proc_open, plus MySQL 8 with performance_schema enabled. Pass credentials through your CI secret/environment facility, not command arguments or checked-in files.

```sh
export BC_CRYPTO_TEST_MYSQL=DISPOSABLE_ONLY
export BC_CRYPTO_TEST_HOST=127.0.0.1
export BC_CRYPTO_TEST_USER=root
# Set BC_CRYPTO_TEST_PASSWORD privately for your disposable server.
BC_CRYPTO_TEST_EDITION=SAAS php VTU/tests/crypto_mysql_integration.php
BC_CRYPTO_TEST_EDITION=NON-SAAS php VTU/tests/crypto_mysql_integration.php
```

`.github/workflows/crypto-mysql.yml` supplies a fresh MySQL 8 service per edition and runs this automatically for relevant changes. The hardcoded CI password protects only an ephemeral service with no customer data; never reuse it elsewhere.

## Assertions

- All seven production tables install as InnoDB; running the additive statements twice succeeds and creates no enabled accounting policies.
- Missing controls and missing independent accounting approval deny admission.
- Independent PHP processes attempting the same reservation reference commit only one operation and two entries, with exact decimal balances and one duplicate response.
- A changed payload cannot reuse an idempotency reference.
- A real MySQL trigger rejects an audit insert; the preceding governance document/revision change and audit count roll back.
- The runner holds an uncommitted platform stop, observes the reservation worker waiting through MySQL lock instrumentation, commits, and verifies that waiting admission rejects the committed stop without journal writes.
- Exact release remains available during stop; a second release fails and the held bucket is untouched.
- A waiting stale editor rejects a newer committed revision rather than overwriting it.
- Available/reserved totals are restored exactly and rejected operations leave no partial entries.

Lock waits are observed, not inferred from elapsed sleeps. Polling and server lock-wait timeouts are bounded, and the CI job has an outer timeout. Failure is nonzero and blocks a successful check.

## Remaining release gates

A passing disposable test is not a deployment approval. It does not prove application/browser authorization flows, real staging schema compatibility, migration backups/restore, restricted DB grants, MariaDB support, production load behavior, custody/account attribution, provider reserves or live Bybit execution. The synthetic opening balances deliberately cannot satisfy a real external reconciliation. Test provider submission-time stops, beneficiary workflows, deposit confirmation processing and operational incident response separately before live activation.
