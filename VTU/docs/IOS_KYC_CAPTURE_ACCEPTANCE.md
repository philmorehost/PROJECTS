# Native iOS live KYC capture increment — three brands

DG7, JIKABIZ and MZEEVTU iOS KYC now expose camera-only face-photo and short-video capture. No gallery source is used for these fields. Camera/microphone permission denial, unsupported hardware/media formats and cancellation are explicit. Photos are orientation-normalized into ≤960-pixel JPEG at0.78 quality, rejected above512KiB. Video capture requests eight seconds/low quality; app-owned temporary copies are exported to MP4 at640×480, inspected for1–9seconds and an audio track, and rejected above3MiB. Temporary source/export files are removed on completion/failure. No camera-roll save is made. Users can discard unsubmitted in-memory captures. Export is compression plus bounded rejection, not a promise every device recording will fit.

Captured files are sent only to the configured HTTPS tenant KYC URL with the persisted app-session bearer (also app_token for multipart transport). No personal integration-key fallback, TLS weakening, raw payload logging or automatic retry is introduced. The dedicated ephemeral upload session refuses redirects, has a90-second request timeout and is invalidated after completion. Server-required setup restrictions remain. Both editions' KYC upload response now includes additive `accepted_media` names; the new client clears captures only after a successful response confirms EVERY submitted capture. Older backends without this acknowledgment yield an explicit unconfirmed/partial message, not a false success. Roll out the matching backend before these clients.

Network uncertainty/partial acknowledgment retains captures in the current screen and directs users to check KYC status. There is no new durable client upload queue or idempotency protocol. Successful upload triggers a status refresh and remains manual review, not automatic approval or biometric liveness attestation. There is no new government-ID/address picker in this increment; use the existing secure web submission for those documents. Native camera work does not itself verify identity, speech, capture origin or defeat virtual-camera/replay attacks.

## Acceptance gates

Python source/resource contracts cover all3 brands, privacy declarations, camera-only UI, byte/duration bounds, authenticated multipart fields, redirect refusal and per-file acknowledgment. Native simulator compilation is separate evidence; simulators cannot prove camera behavior. Required physical iPhone/iPad checks include permission grant/denial/revocation, portrait/landscape/orientation, cancellation/retake, microphone speech, interruption/backgrounding, low memory/storage, export failures, valid/oversize MP4, expired sessions, backend errors/partial acknowledgments and slow/lost responses. Confirm no residual app-owned temporary exports after success/failure and no camera-roll copies. Production signing, distribution and physical-device acceptance remain operator gates.

This code adds no provider execution, financial settlement, deployment or automatic vendor activation. Existing holds are retained. Approved biometric-liveness integration and provider-backed financial services remain separate backlog work.
